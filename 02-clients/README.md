# Clients Directory

## Overview

This directory contains all client-related information, including customer profiles, feedback, requirements, and relationship management documentation. It serves as the central repository for understanding our customers' needs, tracking their success, and managing ongoing relationships.

## Purpose

- **Customer Intelligence:** Centralized information about each client
- **Feedback Management:** Track and analyze customer feedback
- **Requirements Tracking:** Document client-specific requirements
- **Relationship History:** Meeting logs and communication records
- **Success Metrics:** Monitor customer health and satisfaction

## Directory Structure

### Client Folders

Each client has a dedicated folder containing:

- `overview.md` - Company profile, contact information, account details
- `feedback.md` - Product feedback and feature requests
- `requirements.md` - Technical and functional requirements
- `meetings-log.md` - Chronological log of all meetings and interactions
- `deliverables.md` - Agreed deliverables, timelines, and status

## How to Use This Directory

### When Onboarding a New Client

1. Create a new folder: `client-name/`
2. Copy template files from an existing client folder
3. Fill in overview and requirements documents
4. Set up initial meetings-log entry
5. Add client to this README

### When Documenting Client Interactions

1. Update `meetings-log.md` after each interaction
2. Add feedback items to `feedback.md`
3. Update requirements as they evolve
4. Track deliverables in `deliverables.md`

### When Reviewing Client Health

1. Review recent meeting notes
2. Check feedback trends
3. Assess deliverable completion
4. Monitor product usage (reference analytics)
5. Update customer success team

## Client Feedback Process

### Collection
- Regular check-in meetings
- Product usage sessions
- Support ticket analysis
- Feature request submissions
- User interviews

### Documentation
- Log in client's `feedback.md`
- Tag by category (bug, feature request, improvement)
- Add priority and status
- Link to relevant product documents

### Action
- Review weekly in product meetings
- Prioritize in roadmap planning
- Update clients on status
- Close the loop when implemented

## Client Segmentation

### By Status
- **Active:** Current paying customers
- **Pilot:** In trial/pilot phase
- **Churned:** Former customers (with retention notes)

### By Tier
- **Enterprise:** Large contracts, dedicated support
- **Business:** Mid-tier contracts, priority support
- **Professional:** Standard contracts, email support

### By Health Score
- **Green:** Healthy, engaged, satisfied
- **Yellow:** At risk, needs attention
- **Red:** Critical, immediate action required

## Key Metrics to Track

### Per Client
- Contract value and renewal date
- Number of active users
- Usage frequency and intensity
- Support ticket volume
- NPS score
- Feature adoption rate

### Aggregated
- Total Active Customers
- Average Contract Value (ACV)
- Customer Retention Rate
- Net Revenue Retention
- Customer Satisfaction (CSAT/NPS)
- Time to Value

## Best Practices

### Documentation
- Update meeting logs within 24 hours
- Use consistent formatting
- Tag action items clearly
- Link related documents
- Include dates and attendees

### Privacy & Security
- Never commit sensitive personal information
- Use anonymized references when necessary
- Keep confidential information in secure systems
- Follow data protection regulations

### Collaboration
- Share relevant updates with team
- Tag appropriate stakeholders
- Maintain single source of truth
- Use version control effectively
